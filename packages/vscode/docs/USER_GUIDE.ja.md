## 1. Codes Doctor でできること

VS Code で開いているフォルダーを静的解析し、次の内容を HTML レポートにまとめます。

- **God Class**: 責務を抱え込みすぎたクラスを 0〜100 のスコアで順位付けします。
- **技術的負債**: 複雑度、保守性（モジュールの結合度と安定度）、循環依存から算出する 0〜100 のスコアと A〜F の評価です。
- **セキュリティ**: コマンド実行、文字列連結による SQL 組み立て、弱いハッシュ、ハードコードされた認証情報などのパターン検出から算出する 0〜100 のスコアと A〜F の評価です。
- **依存グラフ**: モジュール・クラスの依存関係、関数呼び出し、循環依存、アーキテクチャのレイヤー。
- **SBOM と脆弱性**: npm 依存関係のソフトウェア部品表と、依存関係の脆弱性スキャン（[Trivy](https://trivy.dev/) があれば Trivy、なければ `npm audit`）。

解析エンジンは拡張機能の中で動きます。AI 機能を使わない限り、コードがどこかへ送られることはありません（[9 章](#9-プライバシーとデータの扱い)）。

## 2. インストール

1. [Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=masahirocom.codes-doctor) から **Codes Doctor** をインストールします。ローカルビルドの場合は `code --install-extension codes-doctor-<version>.vsix` を実行します。
2. VS Code 1.90 以降が必要です。
3. アクティビティバーに Codes Doctor のアイコンが表示されます。

## 3. クイックスタート

1. 診断したいプロジェクトのフォルダーを開きます。
2. アクティビティバーの Codes Doctor アイコンをクリックし、**現在のワークスペースを解析** を押します。コマンドパレットの `Codes Doctor: Analyze Current Workspace` でも実行できます。
3. ワークスペースに複数のフォルダーがある場合は、対象を選びます。
4. レポートがブラウザーで開きます。開き方は **レポートを開く方法** で変更できます。

まず **概要・品質** タブを見てください。2 つのスコアと God Class ランキングが表示されます。

## 4. ダッシュボード

| 項目 | 内容 |
| --- | --- |
| **画面・レポートの言語** | English または日本語。ダッシュボード、通知、新しく作るレポート、AI の出力に適用されます。作成済みのレポートは元の言語のままです。 |
| **解析対象の言語** | `自動検出（推奨）` は見つかった対応言語をすべて解析します。特定の言語を選ぶと、その言語だけを解析します。 |
| **レポートを開く方法** | 外部ブラウザー、VS Code の WebView パネル、VS Code の URI ハンドラーから選びます。 |
| **現在のワークスペースを解析** | 解析を実行し、レポートを開きます。 |
| **LLMプロバイダー / APIキーを設定 / 取得 / モデル** | AI レビューの準備をします（[7 章](#7-ai-レビューと-ai-コーディング用プロンプト)）。 |
| **出力モード** | 人が読む `レビューレポート` か、AI コーディングエージェントに貼り付ける `AIコーディング用プロンプト` を選びます。 |
| **出力トークン上限** | AI の出力の長さの上限です。 |
| **LLMレビューを実行 / AIコーディング用プロンプトを生成** | 直前の解析結果に対して AI を実行します。ボタン名は出力モードに合わせて変わります。 |
| **レポート履歴 / LLMレビュー履歴** | 過去のレポートを開き直したり、現在のレポートにある AI 出力を確認したりできます。 |

## 5. レポートの読み方

レポートは 6 つのタブで構成されています。

### 概要・品質

- **技術負債スコア** と **セキュリティスコア** のカード。どちらも 0〜100 で、高いほど良好です。
- 対応言語のファイルが 1 つもない場合は警告バナーが出て、両方のカードが **N/A** になります。これは「何も解析していない」という意味で、「問題がない」という意味ではありません。
- **God クラス ランキング**: God Class スコア順のクラス一覧です。メソッド数・行数・依存数も表示します。60 以上は分割を検討する目安です。
- **モジュール結合度メトリクス**: ファンイン（このモジュールに依存しているモジュール数）、ファンアウト（このモジュールが依存しているモジュール数）、不安定度（`ファンアウト ÷（ファンイン＋ファンアウト）`）。不安定度が 0.8 を超えるモジュールは、多くに依存し、ほとんど依存されていないため、変更の影響を受けやすい状態です。
- **アーキテクチャレイヤー分析**: ディレクトリ名からファイルをレイヤー（Presentation、API、Business Logic、Data Access など）に分類し、レイヤー間の依存マトリクスを表示します。
- **ファイル統計**: ファイルごとの言語・クラス数・行数と、サイズ分布のグラフです。

### 依存グラフ

- **モジュール依存グラフ** と、TypeScript/JavaScript・PHP の **関数呼び出しグラフ**。
- **クラス依存グラフ (D3.js)**: ズームやドラッグができるインタラクティブなグラフです。
- **循環依存検出**: 検出した循環とその長さです。短い循環（2 つのモジュールの相互参照）は比較的簡単に解消できます。長い循環は、抽象化が不足しているサインであることが多いです。

### LLM解析

AI レビューと AI コーディング用プロンプトを実行すると、ここに表示されます。それぞれに **AI向けにコピー（Markdown）** ボタンがあります。

### AST解析

解析したすべてのファイルの構造（インポート、クラスや型とそのメソッド、関数）を表示します。TypeScript/JavaScript と PHP は完全な構文木から抽出し、生の構文木も表示します。その他の言語は簡易的な構造抽出で、その旨がレポートに表示されます。一覧が長い場合は分割して表示されるので、**さらに表示** を押すと続きを読み込みます。

### リスク・セキュリティ

- **技術負債スコア** の内訳（複雑度・保守性・循環依存）と、それぞれの問題点・良い点。
- **セキュリティスコア** と、検出した問題（重要度、カテゴリ、ファイル、行、推奨対応）。

セキュリティの検出結果はパターンに基づく「候補」です。対応する前に、必ず前後のコードを確認してください。コメント、文字列リテラル、リテラルの `RegExp.exec()` 呼び出しは対象外です。

### SBOM・脆弱性

`package.json` とロックファイルに書かれた依存関係を、直接・推移的・開発用に分けて表示します。脆弱性スキャンは、`trivy` が `PATH` にあれば Trivy を使い、なければ `npm audit` を使います。`npm audit` を使う場合は、プロジェクトの依存関係をインストール（`npm install`）しておく必要があります。

## 6. 対応言語

| 言語 | 解析方式 | God Class | 技術的負債 | セキュリティ | 呼び出しグラフ |
| --- | --- | --- | --- | --- | --- |
| TypeScript / JavaScript | 完全な AST | ✅ | ✅ | ✅ | ✅ |
| PHP | 完全な AST | ✅ | ✅ | ✅ | ✅ |
| Python | 簡易抽出 | ✅ | ✅ | ✅ | — |
| Go | 簡易抽出 | ✅ | ✅ | ✅ | — |
| Swift | 簡易抽出 | ✅ | ✅ | ✅ | — |
| C# | 簡易抽出 | ✅ | ✅ | ✅ | — |
| Java | 簡易抽出 | ✅ | ✅ | ✅ | — |
| Kotlin | 簡易抽出 | ✅ | ✅ | ✅ | — |
| Rust | 簡易抽出 | ✅ | ✅ | ✅ | — |
| C++ | 簡易抽出 | ✅ | ✅ | ✅ | — |
| Dart | 簡易抽出 | ✅ | ✅ | — | — |

- **完全な AST** の言語は本物のパーサーで解析します。**簡易抽出** の言語は、括弧やインデントを追跡する構造抽出を使います。一般的な書き方のコードなら、クラス・メソッド・関数・インポートを正しく拾えますが、コンパイラーではありません。
- 依存グラフ、循環依存、レイヤー分析、SBOM はすべての言語で動きます。
- C++ は `.cpp`、`.cc`、`.cxx`、`.hpp`、`.hh` が対象です。`.h` と `.c` は C の可能性があるため対象外です。
- 対応していない言語（Ruby など）のファイルは解析しません。そうしたファイルしかないフォルダーでは「対応言語のファイルがない」バナーが表示されます。
- **解析対象の言語** で `TypeScript/JavaScript` を選ぶと両方を、`JavaScriptのみ` を選ぶと `.js`/`.jsx` だけを解析します。それ以外を選ぶと、その言語だけを解析します。

## 7. AI レビューと AI コーディング用プロンプト

AI 機能は任意です。OpenAI または Anthropic の、ご自身の API キーを使います。

1. **LLMプロバイダー** を選びます。
2. **APIキーを設定** を押してキーを貼り付けます。キーは VS Code のシークレットストレージ（OS のキーチェーン）に保存され、`settings.json` やワークスペースには保存されません。
3. **取得** を押して、そのキーで使えるモデルの一覧を読み込み、モデルを選びます。
4. まだなら解析を実行します。
5. **出力モード** を選び、**LLMレビューを実行** または **AIコーディング用プロンプトを生成** を押します。結果はレポートに書き込まれ、レポートが開き直されます。

### レビューレポート

人が読むための構造レビューを AI が書きます。メトリクスがこのコードベースにとって何を意味するか、主なリスク、次に取るべき対応をまとめます。

### AI コーディング用プロンプト

Claude Code、Cursor、GitHub Copilot、Codex にそのまま貼り付けられる作業指示を AI が書きます。内容は次のとおりです。

- 目的と、その根拠になるメトリクス
- 優先順位を付けた最大 5 件のタスク（対象、根拠、最初に確認すること、変更内容、変更してはいけないこと、完了条件）
- 手を付けなくてよいことと、エージェントに報告してほしい内容

プロンプトに登場するファイル名やシンボル名は、解析結果にあるものだけです。不確かな点は、事実ではなく「確認する手順」として書かれます。**AI向けにコピー（Markdown）** でそのままコピーできます。レビューとプロンプトは別々に保存されるため、片方を生成してももう片方は消えません。

### 出力トークン上限の目安

既定値は 16,000 です。推論しないモデルは 4,000〜8,000、推論モデルは 16,000〜32,000 が目安です（推論分も上限に含まれます）。OpenAI のモデルが上限に達して空の出力を返した場合は、上限を広げて 1 回だけ再試行します。その分、費用が増えることがあります。

## 8. 設定一覧

| 設定 | 既定値 | 値 |
| --- | --- | --- |
| `codeDoctor.displayLanguage` | `en` | `en`、`ja`。アプリケーション全体の設定として保存されます。 |
| `codeDoctor.analysisLanguage` | `auto` | `auto`、`typescript`、`javascript`、`php`、`dart`、`python`、`go`、`swift`、`csharp`、`java`、`kotlin`、`rust`、`cpp` |
| `codeDoctor.reportOpenMode` | `external` | `external`、`webview`、`vscode` |
| `codeDoctor.llmProvider` | `openai` | `openai`、`anthropic` |
| `codeDoctor.llmOutputMode` | `review` | `review`、`agentPrompt` |
| `codeDoctor.llmModel` | 空 | ダッシュボードで **取得** した後に選択 |
| `codeDoctor.llmMaxOutputTokens` | `16000` | 200〜1,000,000 |

## 9. プライバシーとデータの扱い

- **解析** はすべて VS Code の中で行われ、ネットワークには何も送りません。
- **レポート** は拡張機能の保存フォルダーに保存されます。グラフや Markdown 表示のライブラリを内蔵しているので、オフラインでも開けます。Markdown は表示前に無害化され、WebView パネルはネットワークアクセスを遮断します。
- **AI 機能** を使うと、解析結果の要約（メトリクス、ファイルパス、クラス・メソッド・関数の名前）を、選んだプロバイダーに送ります。ソースコード本体は送りません。データの扱いはプロバイダーのポリシーに従います。
- **API キー** は VS Code のシークレットストレージに保存され、選んだプロバイダーにだけ送られます。

## 10. トラブルシューティング

| 症状 | 対処 |
| --- | --- |
| スコアが **N/A** になり警告バナーが出る | フォルダーに対応言語のファイルがありません。ソースコードがあるフォルダーを開くか、**解析対象の言語** を確認してください。 |
| 期待した言語がレポートにない | **解析対象の言語** を確認してください。特定の言語を選ぶと、ほかの言語は解析されません。 |
| **LLMレビューを実行** が使えない、または失敗する | 先に解析を実行し、API キーを設定し、**取得** でモデルを選んでください。プロバイダーからのエラーは通知に表示されます。 |
| AI の出力が途中で切れる、または空になる | **出力トークン上限** を上げてください。推論モデルでは特に重要です。 |
| 保存済みレポートに「AST表示が破損しています」と表示される | **現在のワークスペースを解析** をもう一度実行して作り直してください。元のレポートと AI の結果は残ります。 |
| 脆弱性スキャンで依存関係が未インストールと表示される | プロジェクトで `npm install` を実行するか、`node_modules` がなくてもスキャンできる Trivy をインストールしてください。 |
